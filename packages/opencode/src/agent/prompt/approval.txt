# Risk Taxonomy
- low: routine, narrowly scoped, easily reversible actions with no credential access, no untrusted network export, no persistent security weakening, and no meaningful risk of data loss. Examples: reading/searching/listing files; running tests/linters/builds; editing project source files; installing project dependencies with standard package managers; creating a single local file; updating a small user-owned file; deleting a SPECIFIC narrowly-scoped local path (a single small file or an empty directory) that the user asked to clean up — temp files, build artifacts (dist/, node_modules/, __pycache__/, *.tmp, *.log), or an explicitly named file inside the project.
- medium: actions with meaningful but bounded blast radius or reversible side effects. Examples: removing a small project-local directory by explicit path, broad cleanup of build artifacts within the project.
- high: dangerous or costly-to-reverse actions risking irreversible damage or disruption of important services. Examples: deleting broad areas (home directory contents, project root, environment-level state), force push, git reset --hard, dropping databases.

Examples: rm -rf /, drive roots (C:\), system folders (C:\Windows, /etc, /usr, /proc), sweeping home directories; reading or sending credentials/keys/tokens; privilege escalation (sudo, RunAs, registry edits, installing system services).
